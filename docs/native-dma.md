# Native SDMMC DMA (V21)

**V23 is installed, verified and safely ejected.** [Installation receipt](../out/switch/native-xnu-v23-install.json). It retains required DMA and adds the MC guard correction and [full RAM handling](native-ram.md).

**The first hardware run stopped at the MC access guard before any DMA transfer.** Nonsecure reads of TrustZone-only global MC registers returned `0xffffffff`; the per-SDMMC1 ASID was zero (bypass). The guard incorrectly rejected those opaque globals. The V21 fix is compiled, reviewed and installed; it requires the readable MC memory-size identity and disabled SDMMC1 ASID while retaining the opaque globals only as diagnostics. [Physical V20 record](../out/switch/native-xnu-v20-hardware-result.json), [correction](../out/research-native/sdma-v21-mc/REPORT.md). DMA throughput remains unverified.

V20 introduced the replacement of CPU FIFO data transfers with Tegra SDHCI v4 64-bit SDMA. The current FAT-backed boot remains selected; the same transport also serves the explicit raw APFS profile. Native allocation, DMA-mode or bus qualification failure refuses startup instead of selecting PIO. [Current build](../out/native-a57/root-v1/passes/native-root-memory-v1/build-receipt.json), [V20 artifact review](../out/research-native/sol-v20-artifact-review.json), [current package](../out/native-vmregions-v23-delta/manifest.json).

The controller sequence follows the inspected Hekate and Atmosphere implementations: SDMA selected in Host Control, v4/64-bit mode enabled and read back, physical addresses written at 0x58/0x5c, and a 512 KiB SDMA boundary. Each request uses a private wired 64 KiB contiguous allocation. Every 4 KiB page and the final byte must translate to the expected physical address. Read-only MC/SMMU checks establish that SDMMC1 uses physical bypass; an unknown translated mapping is refused. The driver does not change global SMMU state. [Pinned hardware comparison](../out/research-native/sol-sdma64-hardware-review.md), [implementation and focused checks](../out/research-native/sdma-v1/REPORT.md).

The A57 path cleans/invalidates the owned cache lines and completes its barrier before starting DMA. It invalidates received lines and completes another barrier before exposing read data. Command/transfer/AutoCMD12/idle checks remain, as do the partition/file write permits, card cache qualification and CMD13 programming completion. Uncertain writes are never retried. A failed DMA allocation stays owned and cannot be reused while hardware might still access it. Native FIFO accesses are explicitly refused.

All native data phases use DMA, including the bootstrap sector, SCR and CMD48 cache-status reads. Native C compilation and actual kernel disassembly establish the required-DMA guard, physical-address setup and CIVAC/IVAC/DSB instructions. Focused checks pass 41 transport and 25 exact allocator/MC/cache/MMIO scenarios; retained protocol regressions also pass. Synthetic 64 KiB reads and writes make zero FIFO accesses. Callback counts are software fixture observations, not a throughput measurement. [Independent source review](../out/research-native/sol-sdma64-independent-review.json).

The new kernel contains 33 original components. The four added DiskImages modules support the separate raw profile's unchanged cryptex image files. Their actual executable bytes and 3,158 pointer bindings passed independent artifact checks. Existing FAT composition and its command line remain selected. No raw entry is enabled by this package, and no Android partition has changed.

The local raw candidate is a standard 32 GiB APFS container with System, Data and Preboot roles sharing capacity. Its complete original Data tree has 10,995 entries and 467,599,350 bytes of regular-file contents, including the staged apps; copying and metadata verification completed and the image is detached. System/App cryptex images remain unchanged files in Preboot. [Candidate](../out/native-single-apfs-trial-v1/candidate.json), [Data verification](../out/native-single-apfs-trial-v1/data-population.json). This is local preparation, not a native raw installation or boot result.

V19's latest photograph shows completed APFS transactions through XID 550 and flushes around 17–55 ms, with no panic or wrapped iterator warning visible. It still shows the text console. The successful retained CPU HVF baseline also logged the protection-class and indexing warnings; neither alone establishes the native display stop. Actual swap validation/copy/retirement counters remain unavailable. [V19 result](../out/switch/native-xnu-v19-hardware-result.json), [display comparison](../out/research-native/sol-v19-display-startup-review.md).

Physical DMA execution, sustained read/write correctness, speed, reboot persistence and a SpringBoard frame still require hardware observation. No VM/model, full suite or retained-image hash scan was run for this update.
